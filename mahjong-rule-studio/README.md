# 麻将番型实验室 — Mahjong Rule Studio

规则体系现在是一等数据对象。页面顶部的“管理体系”可以从空白创建或复制体系；每个体系分别保存名称、计分单位、最低和牌分、允许的和牌结构、信号量和计分策略，番型通过 `ruleSetId` 明确归属。旧版 `ruleSet / ruleset / specs / values` 存档会在载入时自动迁移到当前结构。

和牌结构也可以在“管理体系 → 编辑结构积木”中新增、复制和修改。结构编辑器目前提供三类通用生成方式：面子＋雀头拆分、按同牌张数生成单位、指定牌种全部出现；组合龙等旧特殊结构仍保留为适配器。国标七对子使用 `每种牌允许 0/2/4 张、每 2 张生成一个单位、共 7 个单位`，因此四张相同牌会正确贡献两个对子；立直七对子仍只允许 0/2 张。

规则体系还可以声明和牌总张数、允许使用的牌种和每种牌的最大张数。通用“面子＋对子”拆分器支持任意面子数和对子数，例如 8 张的 `2 面子＋1 对子`、14 张的 `2 面子＋4 对子`、17 张的 `5 面子＋1 对子`。国标九莲宝灯按和牌前暗手精确检查 `1112345678999`，只有九面听形才能获得该番种。

一个**真正不需要后端**的静态麻将规则编辑器原型。零依赖、无需编译。支持 Scratch 风格积木条件树与中文表达式积木、通用集合量词与变量、增删番型、自定义信号量、13+1 张手牌与吃碰杠输入、分解和番数计算，以及 JSON 导入/导出。

## 立即使用

1. 解压整个目录。
2. 双击 `index.html`（Chrome / Edge / Firefox 等现代浏览器）。不要只下载 HTML，必须让全部文件位于同一个目录。
3. 在左侧选番型，在中央编辑规则，在右侧输入手牌并点击「检测番型并计算番数」。
4. 修改会保存在当前浏览器的 `localStorage`。请及时「导出 JSON」备份。

也可以把这几个文件上传至 GitHub Pages、Cloudflare Pages 或 Netlify。**无需 Node、服务器和数据库**。`test.js` 仅用于开发测试，不需要部署。

## 文件结构

- `index.html`：网页的结构。
- `styles.css`：布局、麻将牌输入面板、积木的视觉样式。
- `expressions.css`：中文表达式积木（对象、属性、常量、公式参数）的样式。
- `rules.js`：立直麻将预设、3 个原创示例、积木配置、信号量，以及分组排序逻辑。
- `mcr-rules.js`：国标麻将 81 番种数据（七星不靠保留 24 分，作为全不靠的计分特例，不单独建结构）；加载时替换 `rules.js` 里的旧版国标条目。
- `language.js`：番型定义语言；提供集合、组合、划分、变量、量词、属性访问、公式和比较。
- `engine.js`：牌张解析与验证、手牌分解、旧积木兼容、番型覆盖与番数计算。
- `app.js`：番型列表、积木编辑器、信号量和测试面板交互、本地保存及 JSON 导入导出。
- `test.js`：`node test.js` 运行不依赖 npm 的验证测试。

## 牌输入格式

- `1m` 到 `9m`：万子；`1p` 到 `9p`：筒子；`1s` 到 `9s`：索子。
- `1z` 到 `7z`：东、南、西、北、白、发、中。
- 可压缩表示：`123m456p789s55z`。空格可有可无。
- 例：暗手牌 `123m123p123s456s5p`，和牌张 `5p`，能组成三色同顺。
- 每组声明副露占去暗手牌的 3 个结构牌位；暗手牌应填 `13 - 3 × 副露面子数` 张。杠的第 4 张通过副露类型计算。
- 红五暂通过「赤宝牌数量」信号量手动输入，不做五牌的物理区分。

## 番型定义语言

新规则不必等待程序增加一个“专用番型积木”。语言把规则拆为：

1. 集合源：`tiles`、`groups`、面子二元组、三元组、四元组、四面子的两两划分，以及变量内部的局部集合（例如 `g.tiles`）。
2. 量词：存在、全部、不存在、匹配数量。
3. 变量：量词把当前元素绑定为用户命名的变量，例如 `g` 或 `p`。
4. 属性：`g.type`、`g.suit`、`g.center`、`g.family`、`g.open`；组合使用 `g.0`、`g.1`，划分使用 `p.0.0`。
5. 公式：`abs`、`absdiff`、`add`、`sub`、`mul`、`min`、`max`、`count`、`unique`、`same`、`category`、`containsCategory`。
6. 比较：等于、不等于、大于、小于、大于等于、小于等于。

例如，三色同顺现在由“三元面子组合＋属性比较”定义：

```json
{
  "kind": "quantifier",
  "source": "groupTriples",
  "variable": "g",
  "mode": "some",
  "children": [
    {"kind":"compare", "left":"g.0.type", "op":"eq", "right":"\"sequence\""},
    {"kind":"compare", "left":"same(g.0.center,g.1.center,g.2.center)", "op":"eq", "right":"true"},
    {"kind":"compare", "left":"unique(g.0.suit,g.1.suit,g.2.suit)", "op":"eq", "right":"3"}
  ]
}
```

协同和、镜同和、对称和也已经改用通用的 `groupPartitions`、属性和算术公式定义，不再依赖一个写死的“四面子关系”判断器。

### 中文表达式积木

比较式的两侧不再直接显示 `g.type`、`pair.suit`、`"sequence"` 这类源码。`language.js` 的 `parseExpression()` 与 `expressionString()` 在“表达式字符串”和结构之间双向转换，界面则用中文积木渲染：对象（面子、面子组合、雀头、牌、牌种、信号量……）、位置（第几张牌 / 第几个面子）、属性（类型、种类、花色、中心数……）、常量（顺子、刻类、万／筒／索／字、各类牌集合；在数值公式的参数里则按数字处理）。上方“表达式积木”可直接拖到比较式任意一侧或公式参数槽位；修改仍写回原有字符串格式，因此规则数据和引擎完全兼容。无法解析的旧表达式会显示为醒目的“旧表达式”输入框，而不是被丢弃。

公式不再共用一个带下拉框的大积木：每种公式都是独立积木（牌属于类别、含类别牌、全部相同、不同值数量、最小值、最大值、求和、差值、绝对差、数量、属性列表、按条件筛选……），统一归入紫色的“公式积木”区，并按中文语序渲染参数，例如「雀头 牌属于类别 风牌」「第1个面子 与 第2个面子 的绝对差」。逻辑容器标题和量词积木使用绿色，且／或／非保留黄色；比较式单独归入红色「比较判断」区。

量词不再是一个「遍历集合 / 绑定变量」块加模式下拉，而是拆成「存在」「全部」「不存在」「匹配数量」四个独立积木；树里用自然语言显示，例如「存在一个面子的三元组合 g1，使其满足：」「满足下列条件的四面子的两两划分 p 共有 恰好 1 种：」。

每个量词里都有可编辑的变量名（字母、数字、下划线或汉字）；新建时自动生成不会重复的名字（如 g1、g2），旧数据里重复的绑定名会在打开规则时自动编号并同步改写引用。比较式左侧“对象”下拉会按名字列出当前作用域内的变量，例如 `g1`，因此内层比较可以直接引用外层变量。改名时会同步改写该量词子树里所有 `g1.…` 路径以及 `g1.tiles` 这类集合源，并拒绝重名和保留字。

左侧“修改类别名词”可以编辑内置类别的显示名称；绿牌、推不倒和自定义类别还可以直接编辑牌张列表。新增或删除类别会同时作用于「牌属于类别」表达式和「所有牌属于集合」等条件积木；删除被规则引用的类别后，这些条件会不再匹配。

所有番型的根节点统一为逻辑容器（且／或／非）；打开规则时，如果旧数据根节点直接是量词、比较或条件，会自动套入「且」，方便在根部继续添加条件。

一气通贯、清龙、花龙在“中心数 2/5/8”的判定上增加了等差步长为 3 的校验，修正了 123/345/789、123/567/789 这类组合被误判的问题。

九莲宝灯不再是一种分解类型。引擎先按普通四面子一雀头分解，规则再检查同花色，并分别统计序数 1、9 至少三张及 2～8 至少一张。

原创示例中新增「九数贯通」6 番：四面子一雀头、无字牌，1～9 每个数字恰好出现在一个面子或雀头中，例如 `111m234m555p678s99s`。

原创示例还加入七个数字覆盖番：聚五数（1）、聚四数（4）、聚三数（7）、间五数（4）、间四数（6）、间三数（8）、两数（10）。判定统一为无字牌，整手牌的数字被对应等差数列覆盖；允许缺项、不允许出项；多个番同时成立时高番覆盖低番。

## 特殊计分（不完全由积木决定）

以下番种的命中或分值有一部分来自引擎或规则元数据，而不是编辑器里可见的积木：

- **无番和**：`mcr_chicken_hand` 的 AST 是永远不成立的占位；引擎按 id 排除它，并在国标没有任何其他番命中时兜底给 8 分。改它的积木不会改变触发条件。
- **花牌、四归一**：命中由积木决定，但分值由隐藏的 `scoreExpr` 计算（花牌数量；2 × 四归一数量），规则编辑器里的 `closedHan/openHan` 不生效。
- **重复计分番种**：箭刻、双同刻、暗杠、一般高、喜相逢、连六、老少副、幺九刻、明杠使用隐藏的 `repeatMatches`，实际得分 = 基础分 × 匹配次数。根节点统一套「且」后这里曾出现回归，现已修正。
- **宝牌 / 赤宝牌 / 里宝牌**：引擎在 `scoreVariant` 里直接加 `bonus`，没有对应的可编辑番种。
- **不计关系、役满倍数、门清限定**：分别由规则的 `suppresses`、`yakuman`、`openHan:null` 元数据控制；它们可以在规则字段里改，但不是积木。

## 国标麻将预设

页面顶部可在“立直麻将”和“国标麻将”之间切换。`mcr-rules.js` 提供国标 81 个番种，按分值分为 88、64、48、32、24、16、12、8、6、4、2、1 分共 12 组；这些规则没有对应的专用判断函数，全部由规则积木描述。七星不靠作为全不靠的计分特例保留 24 分，但不再单独建立和牌结构；十三幺结构默认启用。

番型库左侧的分组标题由 `R.groupRules()` 统一生成：每个分组只出现一次，国标按分值从高到低排序，不再需要手写的分组白名单。否则 88、32、12、4、2、1 分等分组不在旧白名单中，会被逐条重复追加，导致同一组番种被渲染多次。`test.js` 中有对应回归测试。

例如全带五的数据结构是：雀头序数等于 5；遍历所有面子 `g`；在每个 `g.tiles` 中存在一张序数等于 5 的牌。

### 旧条件模型

全部条件都由数据表示：

```json
{
  "kind": "all",
  "children": [
    {"kind": "check", "key": "shape", "value": "standard", "op": "eq"},
    {"kind": "check", "key": "relation4", "value": "mirrorAroundPair", "typeMode": "family", "differentSuits": false, "op": "eq"}
  ]
}
```

旧版规则仍可导入。v3 首次加载会更新内置规则定义并保留自定义番型、启用状态、信号量和测试手牌；此前直接修改过的内置番型会被新版原子定义替换，升级前应先导出备份。

- 旧的 `relation4`、`crossSuitSeq`、`straight` 等专用积木保留为兼容层。
- 规则积木的新增番型通常只需要组合数据，不再修改 `engine.js` 的 `switch`。
- 只有要增加全新的基础集合、对象属性或公式函数时，才需要扩展 `language.js`。

## 运行逻辑与限制（请阅读）

这是一个可实际使用的**规则编辑器 MVP**，不是经认证的完整立直麻将对局裁判系统。

- 枚举 4 面子 1 雀头、七对子和国士无双结构，并追踪和牌张归属以判断常见听牌形状与荣和暗刻。九莲宝灯现由普通结构上的牌张量词识别。
- 对每种拆解检查所有启用的役种，执行覆盖关系，选择**番数最高**的结果。立直会计算符数与标准点数，结算公式再分放铳、自摸计算每家支付；国标按 8 分底分加番数计算支付。
- 根据输入的「立直、一发、首巡、海底」等信号判断事件役。**不会**从整局出牌历史验证其合法性；用户需要填写一致且合法的信号状态。
- 可以输入吃、碰、明杠、暗杠、加杠；不模拟这些动作的发生时机，也不检验振听、立直宣告过程、责任支付与流局。
- 番牌双风可分别计自风与场风。设有普通、赤、里宝牌的手动总数；不自动从宝牌指示牌推算。
- 默认采用常见的门清/副露番值与役满逻辑，特殊役满双倍计分、人和、流局满贯、规则集差异等尚未内置开关，可自行新建、修改规则扩展。
- 目前不提供多人同步或云端账号。支持拖拽新增积木、嵌套量词和 v3 本地规则迁移；暂不支持直接拖动现有积木重排。
- 软件仅在当前浏览器本地存储规则，清除浏览器数据会清掉本地规则。建议导出文件备份。

## 开发与部署

开发时可以直接打开 HTML。也可用 Python 自带的文件服务器：

```bash
python -m http.server 8000
```

打开 `http://localhost:8000`，部署时上传 `index.html`、`styles.css`、`expressions.css`、`language.js`、`engine.js`、`rules.js`、`mcr-rules.js`、`app.js` 即可。

运行测试（需要 Node.js，但运行网站不需要）：

```bash
node test.js
```

## OpenMahjong 番种包

直接打开 `index.html` 默认进入立直番种简版，列表只显示自制番种；立直原有番种仍由游戏提供，不会随番种包重复导出。新番种默认未启用，勾选后才参与导出。覆盖目标按名称选择，包含立直原有番种和当前体系的其他自制番种；被覆盖的自制番种也需要启用并一起导出。已有浏览器存档不会被重置。

「载入示例」的内容来自 `samples.js`（`../omc-yaku-pack-v3.json` 的内联副本，不走 fetch，所以 `file://` 直接打开也能用），列出包里的 5 条番型：镜同和（3、食下 2）、对称和（3）、东北新干线（1 役满）、协同和（1、门清限定）、九数贯通（6）。选一条就把它加进当前体系（重复选择会按包内容刷新该条，不会重复建条），并按番型名载入一副已经判中的手牌与副露，点「检测番型并计算番数」即可看到番型与结算。示例都以自制番型保存，可以继续编辑或再导出成番种包；覆盖关系沿用包里的定义（目前是镜同和覆盖协同和），没随包导出的覆盖目标会在导出时自动去掉。

游戏目前接受立直番种包，支持的信号与部分积木见 `docs/design/custom-riichi-yaku-prototype.md`。国标包及部分高级公式、类别积木尚未接入游戏。导出时会做两层检查：**结构校验**（id、番数、类别、节点数/深度/体积、信号、公式与集合白名单）和**语义校验**（属性是否适用于该对象、数值公式的参数是不是数字、比较两侧类型是否一致、覆盖目标是否存在于立直番种表），语义问题会直接拦住导出。另外，覆盖目标如果指向本次导出里没有的自制番种（没载入或没启用），会从包里去掉而不是报错——游戏侧只接受引用包内番种或立直原有番种的包。服务端还会再验证一次完整内容。
